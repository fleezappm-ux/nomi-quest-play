# POP 0.41 — 3枚到達時の精算

- 誰かの未精算チケットが3枚以上になると、全員のチケット確定を待ってホストが精算ターンを開始する。
- 9ターンごとの定期精算を廃止。
- チケット受取時のバリア選択を廃止。お助けカードは精算画面の1杯ごとに使う。
- 3枚を1杯として精算し、余りは持ち越す。バリアで杯を無効にしても精算済みのチケットを再請求しない。
- 既存の状態チェックを経由して精算画面へ進む。お助けの使用は任意。
- 精算履歴には既存の sessions/{room}/nv/{round} を使う。ホストの「待たずに進む」でも印を残す。
- Firebase設定、認証、DBルールは変更しない。旧版と新仕様が混在しないよう全員が新URLで新しい部屋を作ること。
- v0.6.1およびルートの単体版は変更しない。新仕様の対象は multiplayer/room の通信版。

## 検証

- 枚数計算: 2→3、2→4の余り1、次回精算、重複請求なし、固定周期なし。
- Chromium 320/360/390/412px: 3枚到達時の自動移行、早期バリアなし、精算バリア、ホスト次ターン、再接続。横はみ出し・画像不良・JS例外なし。
- 既存ルールのローカル評価器: 任意ターンのcheck遷移、状態回答、結果、精算バリア、消費記録、精算履歴、次ターン書込を許可。Firebase Emulatorや実通信の代用と断定しない。
- NPC2人との通常時間20ターン通しプレイ: ホーム→登録→開始→精算→終了→ホーム復帰。13種類（12カード＋check）を通過、JS例外・外部リクエストなし。
- Android実機・実際の複数台通信は未確認。

## 変更ファイル

- ten.js: 3枚監視と精算遷移、精算履歴購読、受取時の選択廃止、精算/所持/終了の残数表示。
- index.html: 遊び方、バージョン。
- room.js / npc.js / oni.js: importのバージョン更新のみ。
